# Rote Extension

支持 X、GitHub、YouTube、B站、Hacker News、arXiv、Bluesky，并通过右键保存普通网页或选中文字。使用 WXT、TypeScript、React、Manifest V3 和 Bun，开发者模式加载。

## 安装

1. 解压发布 ZIP，保留整个 `chrome-mv3` 文件夹。
2. 打开 `chrome://extensions`，开启「开发者模式」，点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的 `chrome-mv3` 文件夹。
3. 点击浏览器工具栏的 Rote 图标，直接打开独立设置标签页，填写 `https://rote.ink` 和 OpenKey。官方地址会自动转换为 `https://api.rote.ink`；自部署实例请填写 API 根地址。
4. OpenKey 需要 `SENDROTE`、`UPLOADATTACHMENT`、`GETROTE`。点击连接并批准该 API 域名访问权限。
5. 刷新已经打开的 X 页面，打开某条帖子的分享菜单，点击「保存到 Rote」。
6. 首次上传时，如果对象存储使用另一个域名，文字先保存；在「最近采集」点击授权并重试，只授予任务实际使用的上传域名。

更新时替换原文件夹内容，然后在扩展管理页点击重新加载，并批准新增站点与右键菜单权限，并刷新已经打开的目标页面；关闭升级前已打开的设置页，再点击工具栏 Rote 图标重新打开。不要删除扩展再安装，否则浏览器会清除本地配置和待恢复任务。

## 保存内容

- 当前帖子完整可见文字和原帖链接，不额外添加作者、账号和发布时间。
- 全部静态图片按原顺序上传为附件；每张支持 JPEG、PNG、WebP，最大 20 MiB。
- 引用帖只保留链接；不采集评论、线程、视频、GIF 视频、外链文章正文或截图。
- 正文有「显示更多 / Show more」时拒绝保存，提示先展开。不自动翻译。
- 创建普通笔记，使用设置中的默认标签与可见性；首次安装及旧版本升级默认仍为私密、无标签。

同一服务地址、OpenKey、平台和内容 ID 对应一个本地任务。再次点击已保存帖子不会创建重复笔记。更换 OpenKey 会切换任务空间。

## 默认标签与可见性

在扩展设置中填写「默认标签」，使用中英文逗号分隔，例如 `X, 阅读`；自动去除重复项和开头的 `#`。留空则不加标签。最多 20 个标签，每个最多 50 个字符，与 Rote 接口限制一致。

「自动添加平台标签」默认关闭。开启后，采集 X 帖子会添加 `X` 标签，采集 GitHub 项目会添加 `GitHub` 标签，与默认标签去重；含平台标签在内最多 20 个标签。此开关只影响新采集任务。

「默认可见性」可选私密或公开。保存设置后，仅新采集任务使用新值；已保存笔记和待恢复任务沿用采集时的值。升级前的旧任务继续使用私密、无标签。公开模式下，新笔记将在 Rote 中公开可见。

## 失败恢复

- 文字已保存、图片失败：任务保留笔记 ID、上传清单和已下载 Blob，重试仅补传同一条笔记。
- 创建响应丢失：标记「待核对」，不会自动再次创建；点击核对后搜索来源链接，只有正文完全一致且唯一命中时关联原笔记。
- Worker 停止或页面关闭：任务存在 IndexedDB；重新唤醒 Worker 后恢复。创建中的请求会转为待核对。
- 已成功的任务会释放图片 Blob。任务记录用于去重，浏览器清除扩展数据后不再保留本地去重历史。

## 开发

```sh
bun install --frozen-lockfile
bun run dev
bun run check
bun x playwright install chromium
bun run test:e2e
bun run zip
```

生产加载目录：`.output/chrome-mv3`。自动化使用真实 Chromium 加载生产构建，X / GitHub / YouTube DOM 和 Rote API 在本地模拟；不会自动访问真实账户或创建线上笔记。

## 架构和权限

`src/sites` 是站点适配层，负责目标绑定、提取、菜单、提示及生命周期。内容脚本只提交 `CaptureItem`。`src/messaging` 校验消息与来源，`src/tasks` 在后台持久化和执行任务，`src/rote` 提供浏览器 fetch 客户端。

OpenKey 只在扩展可信上下文存取，storage.local 设置 `TRUSTED_CONTEXTS`。不会注入网页，也不使用 Rote Cookie。GET OpenKey 参数遵循现有服务端协议，POST 放在 JSON 请求体。发布包不含任何账户配置或测试密钥。

默认主机权限为 X、GitHub、www.youtube.com，以及图片 CDN `pbs.twimg.com` 和 `i.ytimg.com`。可选 HTTPS 匹配范围用于运行时申请用户配置的具体服务/上传域名，不会在安装时获得所有站点权限。localhost HTTP 仅用于本地开发实例。

网络请求均从扩展后台发出。有对应 host permissions 时通常无需修改 Rote 或对象存储 CORS。参见 [Chrome 跨域请求文档](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。

扩展页面复用 Rote Web 设计变量、Button/Input 和标识。注入 X 的菜单不加载 Tailwind 或全局 CSS，只读取相邻菜单项的计算样式；提示使用独立 Shadow DOM。详见 [组件来源](docs/SOURCES.md) 和 [验收记录](docs/VERIFICATION.md)。

## GitHub 项目与双栏布局

打开 github.com 的公开仓库首页，在 Star 右侧点击「保存到 Rote」。笔记只含 owner/repo、简介（有则添加）和仓库链接，不包含 README 或图片。私有仓库、Enterprise、Issue、PR、文件页不提供入口。按钮沿用 GitHub 原生样式；保存中和已保存时禁止重复点击，失败可在设置页重试。

桌面设置页使用 Rote 主布局的页面滚动方式：左侧设置 sticky 停留，右侧列表随页面滚动，没有内部滚动容器。窗口较矮时，左侧随页面滚动至底部再停留，保存设置按钮始终可达。800px 及以下恢复单栏。

更新到 0.2.0 后需要同意新增的 github.com 访问权限，并重新加载扩展、刷新 GitHub 和 X 页面。

## 统一保存提示

X 与 GitHub 使用同一套 Rote Toast：底部居中、保存状态原位更新、成功后 6 秒消失；失败或待核对时保留「打开设置」恢复入口。手动关闭后不会因同一任务更新再次弹出。提示颜色跟随系统深浅主题，样式隔离在 Shadow DOM 内。网站菜单和按钮仍使用各自原生样式。

## YouTube 视频

支持桌面 www.youtube.com 的视频卡片「⋮」菜单，以及播放页分享/保存旁的独立按钮。笔记包含完整视频标题、频道名称、规范视频链接和一张封面附件。使用视频 ID 去重，列表与播放页共享状态；不保存播放进度、播放列表参数、视频文件、字幕、简介或播放器广告。不支持 Shorts 专用页面。

封面使用该视频的 hqdefault.jpg，经过现有附件上传及失败恢复流程。开启自动平台标签时添加 YouTube。安装更新后允许新增的 YouTube 与封面 CDN 权限，并刷新已打开的页面。


## 0.4.0 新增采集

| 站点 | 入口 | 保存内容 |
|---|---|---|
| B站 | 播放页分享操作旁 | 标题、BV 链接、封面；不含简介 |
| Hacker News | 条目详情的作者／评论操作行末尾 | 标题、原文链接、主帖正文、讨论链接；不含评论和分数 |
| arXiv | 摘要页右侧下载列表下方 | 标题、摘要、链接；不下载 PDF |
| Bluesky | 帖子详情的更多菜单末尾 | 正文、链接、全部静态图片；引用帖只保留链接 |

四站点仅支持详情页，不支持列表卡片采集。B站和 Bluesky 从首页站内跳转到详情页也支持；服务端读取使用公开接口，不需要站点账号 Token。B站 AV 地址归一到 BV，Bluesky 使用 DID 与帖子 ID 去重。

在普通 HTTP／HTTPS 网页空白处右键选择「保存当前网页到 Rote」，保存标题和链接；选中文字后选择「保存选中文字到 Rote」，额外保存原文及换行。直接使用默认标签和可见性。浏览器内部页、本地文件、PDF 阅读器及 iframe 内独立采集不支持。

通用收藏按完整页面 URL 去重，摘录按 URL 与完全相同文字去重；不同摘录分别建笔记。查询参数和锚点保留。通用采集与站内专门采集独立去重，不自动抓取网页全文、图片或摘要。

开启自动平台标签时，已适配域名使用平台名称，其他站点使用完整小写域名，与默认标签去重；仍遵守 20 个标签、每个 50 字符限制。标签不符合限制时提示调整设置，不截断标签。

新增 contextMenus、activeTab、scripting 用于用户主动右键采集和临时 Toast，不常驻读取所有网站。新增站点与图片／公开 API 域名权限用于专门采集。OpenKey 始终只保存在扩展可信上下文，后台执行 Rote 请求。页面关闭或 Worker 重启后的状态在最近采集中查看。

### 0.4.1 修复

修复 Bluesky「更多」菜单在鼠标按下时已打开、扩展却等到 click 才绑定帖子而漏掉入口的问题；同时支持键盘打开和已打开菜单的原生按钮关联。更新加载目录后，在扩展管理页重新加载，并刷新 Bluesky 页面。

### 0.4.2 正文简化

新采集的 Bluesky 笔记只包含帖子正文和原帖链接，静态图片仍作为附件上传。不再向笔记正文添加作者名称、账号和发布时间；最近采集列表仍可显示作者，已有笔记不自动修改。

### 0.4.3 统一精简笔记正文

所有来源均不再额外附加作者、账号、频道名称、UP 主或发布时间。X／Bluesky 保留正文、来源与引用链接；YouTube／B站保留视频标题和链接；HN 保留标题、主帖正文、原文与讨论链接；arXiv 保留论文标题、摘要和链接。GitHub 的 owner/repo 是项目标识，继续保留。图片附件照常保存。原文或标题本身包含的人名、账号、时间不会被删改。此规则用于新保存的笔记，已有笔记不自动修改。
